## Measurement Repairs

The initial stricter dense verifier treated every injected boundary candidate
as if it had to appear in the terminal or provisional retained ledgers. That
definition was wrong: retained ledgers are not exhaustive, and some injected
candidates are merge-valid but not phase-feasible successor edges.

Measurement Repair 001 fixed the observability layer by adding Exp006-only
public measurement records:

- sorted unique transition-component cache entries;
- append-only actual scored edge occurrences;
- per-block resource counters;
- class-coverage records at input, post-future-equivalence, reserved, and
  final export stages.

## Interpretation

The positive synthetic result supports the narrow claim that the Exp005
failure was an unconditioned transition-potential problem, not a missing
candidate, insufficient local frontier width, or mandatory global replay
failure. Boundary-pair evidence can rank the exact multi-jump path above the
shortcut while preserving the false-section controls in this frozen synthetic
matrix.

This does not establish real-data acceptance. The experiment did not test:

- BeatThis cache noise or period-estimate reliability on real songs;
- `.osu` redlines, object placement, or weak-evidence corroboration;
- external BPM or variable-BPM source checks;
- schedule16 selection or repair80;
- holdout100, broad500, or full5050;
- ramp sections;
- production fitter/provider/evaluator/runner integration;
- long-song decomposition behavior or assembly seam drift on real tracks;
- cumulative phase error relative to the current timing module on the corpus.

Recommended next step: `TEST` a separate real-cache protocol card that starts
with schedule16 selection and repair80 only. Do not infer authorization for
holdout, broad, full5050, production rollout, ramp support, or network
validation from this synthetic pass.
