## 建议

优先安排 **音频资产／表示缓存 + 一个约20M参数的干净谱面基底预训练 + 固定模型的多种子长程压力测试**。如果前置任务提前完成，再运行已冻结目标的音频／谱面局部对齐预训练。

这些任务可以在没有人类逐次判断生成质量的情况下产生有用产物。机器负责完成计算、检查机制与数值、报告泛化和失败，最终风格／可玩性采用仍留待集中复核。计算任务不能依赖人在度假期间回答临时架构问题。

本篇是任务组合建议，不是已接受的 Experiment Card，也不是已经启动的后台队列。大模型训练、音频提取与对齐入口仍需实现和预检；当前已有完整生成及恢复入口可复用。长程目标保持 active，本篇没有缩减其要求或替换工作候选。长期任务执行前，应为选定任务分别冻结输入、实现、预算和可自动判断的停止条件。

实测可用资源为24GiB内存、10个逻辑CPU，数据卷约221GiB可用空间。硬件为当前实验使用的M5 Air。现有3.08M参数候选可在CPU1低于数GiB的内存占用下训练／生成，但不能直接把其速度按参数量外推到更大模型或音频编码器。

## 任务A：全TRAIN音频资产与特征缓存

**优先级最高。** 即使下一阶段改变编排模型，这批有精确时间坐标的音频资产仍可复用。

先做内容散列、重复关系、解码有效性、时长与采样率登记、谱面时间范围与音频时间轴检查。报告无法确认的偏移或缺失，不自动猜测修复，也不修改原始音频、谱面或分组。发现跨split关联时单独登记，不能静默把它加入训练。多难度关联保持为同一音频的多个编排，而非复制音频训练样本。

建议保存两级信息：

- 较高时间分辨率的声学特征，例如128频带、100Hz的log-mel；保留毫秒级谱面标签，不把目标强行量化到帧格上。
- 一个冻结的音乐编码器提供的帧级表示，保存少数预先选定的层并降采样到25Hz，供音色、织体与局部音乐上下文使用。它不能替代前一层的精细时间信息。

可把[MERT-v1-95M](https://huggingface.co/m-a-p/MERT-v1-95M)列为研究对照：官方模型卡给出24kHz输入、75Hz特征、768维隐藏表示，并标注权重许可CC-BY-NC-4.0。因此不要把它未经单独选择就写成最终产品必须依赖的编码器。缓存格式应允许替换编码器，并固定权重与实现版本。其[MERT论文](https://arxiv.org/abs/2306.00107)提供音乐自监督表示的近邻，但不构成节奏游戏对齐有效性的证明。

按当前184.714小时、不去重、不压缩的float16载荷计算：128×100Hz的mel约17.0GB；每层768×25Hz的表示约25.5GB。两层加mel约68.1GB，落在建议的80GiB特征预算内。保存全部13层原生75Hz表示将接近1TB，不适合当前磁盘。上述是载荷估算，不是已生成缓存，实际还需扣除无效尾帧并计入索引、边界与文件开销。

长音频必须分块推理并正确拼接帧时间；不能把72分钟波形整体送入注意力网络。自动检查分块边界、时间偏移、重复帧、缺帧和有限值。先固定短片段参考与跨块一致性测试，再批量执行。产物是可校验manifest、关联索引、特征分片与异常列表。

**预算窗口：最多16小时。** 先用固定少量文件实测吞吐；若完整编码超出预算，按预定分片顺序保存完成部分及游标，不降低规格来伪装完整完成。只要索引／原始声学层已完成，它们本身仍是有用结果。自动验收限于数据与时间轴完整性，不宣称“已学会音乐对齐”。

## 任务B：约20M参数的谱面基底长期预训练

这是最值得分配连续一天以上算力的模型任务。它检验目前小模型是否受到容量与暴露量限制，并留下可用于后续音频条件适配的结构基底。

建议从干净的R1基底开始，保留完整行、精确占用／时钟、种子和长期记忆的接口；本次不同时更改时间生成目标、加入音频与堆叠新的恢复模块。20.18M是主候选，9.38M是预先定义的资源备选；35.18M只有实测吞吐和内存表明合算时才进入正式卡片，不在无人值守过程中临时扩张架构。

用全部合格TRAIN源谱面预训练，保持曲组层面的采样与隔离。建议初始目标为30M–60M普通起音暴露，并设硬性壁钟上限。这个范围约为源起音总量的3–6倍，但group-uniform重复采样不等于完整扫过3–6个epoch，必须另报去重覆盖。每个固定检查点保存普通似然、LN/TAP分项、训练／固定VAL差距和少量完整原生延续，避免只留下更低训练loss。

最近的原生恢复实验证明，过强的全参数修正可能以削弱LN来改善某项统计。因此这次基底预训练不自动把生成后的低风险计数当奖励，也不拿机器语义判断冒充标注。更大模型仍可能使用给定的未来骨架形成捷径；迁移到自由时间生成是否有效是之后要测的事。

[计算与数据共同扩展的研究](https://arxiv.org/abs/2203.15556)是容量／暴露分配的近邻，但其文本模型比例不能直接套到4K事件行。当前约11.5M物理行还包含同曲多难度相关性，没有本语料的scaling law。这里选择20M是一个可检验的Mac研究规模，不是已知最优参数量。相比直接投入数亿参数，先得到实测的容量收益曲线更有决策价值。

**预算窗口：主训最多44小时。** 正式运行前做CPU/MPS、批量和长历史内存预检，固定最后方案；达到暴露目标、壁钟预算、预先定义的平台停滞条件或资源门槛之一即停止并保留有效检查点。平台停滞条件必须在小样本预检后冻结，不能让代理在度假期间依据反复查看VAL任意改规则。产物包括可恢复权重、完整配置、实际覆盖／资源账本、固定检查点报告；失败也保留明确的否定证据。

## 任务C：原生轨迹库与多种子长程压力测试

这是当前已有入口最容易扩展的任务。生成、原始历史恢复、精确机制检查和osu!导出均有现成实现。适合在模型训练之外串行填满剩余计算预算。

分两个严格独立的产物：TRAIN原生轨迹可以成为后续恢复学习的候选数据；固定VAL压力测试只用于评估，不能回灌训练。预先按2–6★来源、LN／TAP、时长、密度变化和慢段到密段转换分层，冻结多个随机种子。建议以约1,000–3,000份完整延续作为初始规模范围，实际完成量由吞吐与预算决定，不以选择性保留成功样本凑数。

自动记录持续固定占用、起音集中、局部重复、头／尾后的再击间隔、原生星级与种子间差异，生成最坏片段的完整上下文包。LN比例和重复计数只负责定位，不能自动判成LN协调或塌缩；不把Jack／Trill当违禁图形。机器偏好数据只保存可重算的物理事实、支持集合、原生前缀与来源，不发明“好玩”标签。

**预算窗口：最多8小时。** 产物是生成分布和失败地形，以及下一轮可以直接读取的TRAIN状态库。自动任务可以证明某个候选失败或筛出待复核候选；不能因数千份都合法，就自动宣布可玩性通过。

## 任务D：音频与谱面局部对齐预训练，作为后续可选任务

当音频缓存和稳定的谱面编码接口就绪后，可训练局部对齐／检索或条件适配模块。源谱面的绝对时间能提供自动对齐样本，无需新增人工标签；同一音频的不同难度必须作为相关的有效视图，而非互相充当负例。

这个任务应测试音乐片段与谱面组织之间的关联，不能只做整首歌身份分类。预检应包含同曲邻近但错位片段、重复段、不同难度、稀疏和LN-rich片段，检查模型是否仅凭曲目身份或平均密度取巧。若采用对比式目标，必须先冻结正负样本定义、时间容差和测试切分；当前尚未完成这一步，所以不能立即丢给无人值守训练。

**预算窗口：另加12–24小时，或使用前面提前完成的余额。** 产物是可复用的音频投影／融合初始化和匹配诊断，不是已经验证的音频条件生成器。它比从零预训练一个通用大型音乐编码器更直接利用现有已对齐语料；是否改善生成仍需后续固定骨架对比。

## 暂不安排的长跑

时间骨架生成是下一阶段的重要方向，但当前必须先明确H起音与可释放候选时间的职责、时间表示和生成时的合法完成性。表示尚未冻结时，让一个大型模型训练几天，可能只会固化错误的任务定义。可以先做数据准备与小规模探针，待合约确定再进入长训。

也不安排无界的自动超参数搜索、用agent标签扩充human gold、只凭单个短间隔阈值优化整曲、在VAL上不断产生新修正、或从本地约185小时音频从零追求通用数亿参数音乐基础模型。它们的额外计算不保证给当前最终任务留下可迁移成果。

## 默认72小时队列与无人值守行为

以下是**预算分配**，不是实测完成耗时；还有入口实现与预检工作，尚未启动队列。

| 顺序 | 壁钟上限 | 输出 |
| --- | ---: | --- |
| 预检与冻结 | 2小时 | 数据／依赖检查、CPU/MPS实测、最终模型规模与配置 |
| A 音频索引与缓存 | 16小时 | 完成分片、可恢复游标、时间轴与异常审计 |
| B 谱面基底预训练 | 44小时 | 固定检查点、覆盖与验证报告 |
| C 原生压力测试 | 8小时 | 固定种子分布、最坏案例包与TRAIN状态库 |
| 归档与汇总 | 2小时 | 产物校验、运行账本与简明结果摘要 |

超过三天时，优先将额外时间用于通过预检的主训练延伸或D对齐任务，而不是自动新增一批架构。提前完成的阶段将余额交给已冻结、依赖满足的下一任务；未就绪任务不会凭空宣称可运行。

无人值守执行器需要明确落实以下行为，当前不是已经配置好的服务：

- 一次只运行一个重计算任务。插电且机器可持续唤醒时运行；用户回来或电源条件不满足时，在安全边界暂停。上限覆盖整个队列，休眠不会被记成已经完成训练。
- 建议初始峰值进程footprint上限12GiB，并同时监测RSS、MPS驱动内存、可用内存和swap增长。具体门槛须由预检冻结；持续内存压力或系统热状态恶化时保存并停止，不能靠不断重试继续占用。
- 总新产物上限100GiB，音频特征上限80GiB，磁盘保留至少100GiB。固定检查点轮换只作用于该任务自有的临时产物，基线和原始数据不删除。
- 分片原子提交、每个文件有校验身份；训练按可验证的优化器边界保存，恢复保持配置、数据游标和随机状态。不可恢复的身份或数值错误直接结束该任务，独立后续任务可继续。
- 依赖与需要的模型在预检时固定，正式运行不依赖网络。异常写报告，不向度假中的用户连续索要决策，也不静默修改实验目标。
- 自动报告只给出通过的工程门槛与量度，不自动修改human标签、替换正式候选、推送远端或宣布最终质量验收。

这样用户回来时可以拿到可加载的权重、可以复用的音频资产和具体失败例子，而不需要先整理几天散乱的日志。
